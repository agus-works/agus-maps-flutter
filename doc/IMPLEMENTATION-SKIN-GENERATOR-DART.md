# Implementation Plan: Cross-Platform Dart Skin Generator

## Goal
Replace the current Qt/C++ based `skin_generator_tool` and the `generate_symbols.sh` bash script with a pure, cross-platform Dart solution. The current setup requires a heavy toolchain (Qt6, CMake, Ninja, Python3) and uses bash scripts that are poorly supported on Windows. The new solution will be a unified Dart tool that works identically across macOS, Linux, and Windows.

## Feasibility
**It is 100% feasible and highly recommended.** 
By leveraging the Flutter SDK (which developers already have installed for this project), we can use a headless `flutter test` environment to gain access to `dart:ui`. This allows us to rasterize SVGs and generate PNG texture atlases entirely in Dart without needing Qt, ImageMagick, or any external rendering tools.

## Proposed Architecture

We will create a new standalone Dart package at `tool/skin_generator_tool/`.

1. **Headless Execution:**
   - We will run the generator using `flutter test tool/skin_generator_tool/test/generate_test.dart`.
   - Using `flutter test` provides a headless environment with full access to `dart:ui` (for Canvas, Image, and SVG rendering), which is normally unavailable in pure CLI Dart.
2. **SVG Rasterization:**
   - We will use `flutter_svg` to parse and render SVGs onto a `dart:ui.Canvas`.
   - PNG symbols will be loaded directly using `dart:ui.instantiateImageCodec`.
3. **Texture Packing:**
   - We will implement a custom 2D bin packing algorithm (e.g., Shelf Packer or MaxRects) in Dart to replace the `m2::Packer` from C++.
   - All symbols will be packed into a power-of-2 sized texture.
4. **XML Manifest Generation:**
   - We will use the `xml` Dart package to generate the `.sdf` file, matching the exact XML structure required by the C++ engine.
5. **Wrapper Script Elimination:**
   - The current `generate_symbols.sh` loops over resolutions (mdpi, hdpi, etc.) and themes (light, dark). 
   - We will implement this loop directly inside the Dart script, completely removing the need for a shell script.

## System Requirements & Installation

With this Dart implementation, the heavy C++ build dependencies are eliminated.

### Eliminated Dependencies:
- Qt6, CMake, Ninja, Python3, GCC/Clang/MSVC.

### Required Dependencies:
1. **Flutter SDK:** Already installed by the developer.
2. **OptiPNG (Optional but recommended):** Used for compressing the generated texture atlas.
   - **Windows:** Can be installed via winget: `winget install -e --id=OptiPNG.OptiPNG` (or via Chocolatey: `choco install optipng`)
   - **macOS:** `brew install optipng`
   - **Linux:** `sudo apt install optipng`

## Proposed Changes

### 1. `tool/skin_generator_tool/`
Create a new Dart package with its own `pubspec.yaml`.

#### [NEW] `tool/skin_generator_tool/pubspec.yaml`
Will contain dependencies: `flutter_svg`, `xml`, `path`, `args`.

#### [NEW] `tool/skin_generator_tool/lib/packer.dart`
Implementation of a 2D bin packing algorithm to arrange symbols on the texture atlas.

#### [NEW] `tool/skin_generator_tool/lib/generator.dart`
The core logic for reading symbols, scaling them, rendering to a canvas, and writing the PNG and XML (`.sdf`) files.

#### [NEW] `tool/skin_generator_tool/test/generate_test.dart`
The entry point that will be executed via `flutter test`. It will orchestrate the loops for different sizes and themes previously handled by the bash script.

### 2. `thirdparty/comaps/tools/`
#### [DELETE] `thirdparty/comaps/tools/unix/generate_symbols.sh`
This bash script will be fully replaced by the Dart tool.

### 3. Documentation
#### [MODIFY] `README.md` or `GUIDE.md`
Update the developer setup instructions to remove Qt6/CMake requirements for the skin generator and add instructions for installing `optipng` on Windows/macOS.

## Verification Plan
1. Run the new Dart generator against the existing symbols in `thirdparty/comaps/data/styles/`.
2. Compare the output PNG (`symbols.png`) and XML (`symbols.sdf`) files against those generated by the legacy C++ tool to ensure parity in packing coordinates and rendering quality.
3. Verify the generator runs successfully on both Windows and macOS.
